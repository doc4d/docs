クライアント/サーバー

これらのキーは クライアント/サーバーアプリケーション のオプションを設定します。これらは <CS> ノードの下に配置されます。

<Preferences4D>
  <BuildApp>
    <CS>
      <BuildServerApplication>True</BuildServerApplication>
      <BuildCSUpgradeable>True</BuildCSUpgradeable>
      <IPAddress>myserver.example.com</IPAddress>
      <CurrentVers>3</CurrentVers>
    </CS>
  </BuildApp>
</Preferences4D>

概要​

キー値説明

BuildCSUpgradeableTrue / Falseクライアント更新用アプリケーションをビルドします
IPAddressIP アドレスまたはホスト名クライアントが使用するサーバーのアドレス
PortNumberポート番号クライアントが使用するサーバーの TCP ポート
ServerSelectionAllowedTrue / False接続失敗時にサーバー選択ダイアログボックスを許可します
HardLinkテキスト (最大 31文字)クライアントおよびサーバーアプリケーションの署名
CertificateAuthoritiesCertificatesパスクライアントがサーバーの TLS 証明書を検証するために使用する、信頼できる認証局のリスト
CertificateDomainNameテキストサーバーの TLS 証明書の信頼できるドメイン名
CurrentVers数値ビルドされるアプリケーションの現在のバージョン
RangeVersMin数値接続を許可するクライアントの最小バージョン
RangeVersMax数値接続を許可するクライアントの最大バージョン

ビルド​

BuildServerApplication​

値: True / False (デフォルト)

True の場合、クライアント/サーバーアプリケーションがビルドされます。4D Server のパスは ServerWinFolder または ServerMacFolder キーを使用して設定する必要があります。

BuildCSUpgradeable​

値: True / False (デフォルト)

True の場合、ダウンロード可能なクライアント更新用アプリケーションが macOS および Windows 用にビルドされます。

接続​

IPAddress​

値: IP アドレスまたはホスト名

サーバーのアドレスです。4D には内部的なネットワーク機構が備わっているため、このキーは必須ではありませんが、場合によっては (WAN、特定のポート番号など) 必要となります。クライアント接続の管理 を参照してください。

アドレスは、クライアントアプリケーションの Database フォルダー内にある "EnginedServer.4Dlink" ファイルに保存されます。

PortNumber​

値: ポート番号 (デフォルトは 19813)

サーバーの TCP ポートです。このキーは、サーバーのポートが変更されている場合にのみ必要です。ポートは、クライアントアプリケーションの "EnginedServer.4Dlink" ファイルに保存されたアドレスに追加されます。

caution

このキーはクライアント側のポート番号のみを変更します。サーバー側では、アプリケーションを生成する 4D データベースのポート番号が使用されます。カスタムポートを使用するサーバーをビルドするには、BUILD APPLICATION を呼び出す前に SET DATABASE PARAMETER を使用します:

tempport:=Get database parameter(Client Server Port ID)
SET DATABASE PARAMETER(Client Server Port ID;21000)
BUILD APPLICATION("")
SET DATABASE PARAMETER(Client Server Port ID;tempport)

ServerSelectionAllowed​

値: True / False

自動接続の機構が失敗したときに表示されるエラーダイアログボックスを設定します:

  • True: ダイアログボックスからサーバー選択ウィンドウにアクセスできます。
  • False: ダイアログボックスからサーバー選択ウィンドウにアクセスできません。

起動時に Alt (Windows) または Option (macOS) キーを押すと、常にサーバー選択ダイアログボックスが表示されます。エラー時のサーバー選択ダイアログボックス使用の可・不可 を参照してください。

注

バイナリーデータベースでは、このキーには アプリケーション展開に新しいアーキテクチャーを使用 互換性オプションが必要です。

HardLink​

値: テキスト (最大 31文字)

クライアントおよびサーバーアプリケーションの署名です。

CertificateAuthoritiesCertificates​

値: パス

信頼できる認証局 (CA) のリストと、サーバー証明書のドメイン名を含むファイルのパスです。このリストはクライアントアプリケーションにコピーされ、接続時に 4D Server から送信される証明書の検証に使用されます。

このキーは、クライアント/サーバーアプリケーションに独自の TLS 証明書をインストールする場合に便利です:

  1. カスタムの key.pem および cert.pem ファイルを、ビルドされたサーバーアプリケーションの Resources フォルダー (サーバー実行ファイルの隣) にコピーします:

    • Windows: Client Server executable/<ApplicationName> Server/Resources
    • macOS: Client Server executable/<ApplicationName> Server.app (Resources フォルダーはパッケージの第1階層にあります)

  2. 認証局の証明書 (通常は認証局自身から提供されます) を PEM 形式の信頼できる CA のリストに追加し、このリストのパスを CertificateAuthoritiesCertificates キーに渡します。

    リストは 1つ以上の証明書を含むテキストファイルで、各証明書の前にはタイトルを付けることもできます。たとえば、ルート CA と中間 CA がある場合は次のようになります (証明書の内容は省略しています):

    信頼できる CA のリスト (PEM)
    Root CA
    ===========================================
    -----BEGIN CERTIFICATE-----
    MIIDdTCCAl2gAwIBAgILBAAAAAABFUtaw5QwDQYJKoZIhvcNAQEFBQAwVzELMAkG
    ...
    -----END CERTIFICATE-----

    Server CA
    ===========================================
    -----BEGIN CERTIFICATE-----
    MIIEkjCCA3qgAwIBAgIEOGPe+DANBgkqhkiG9w0BAQUFADCBtDEUMBIGA1UEChML
    ...
    -----END CERTIFICATE-----

詳細については、こちらのブログ記事 を参照してください。

CertificateDomainName​

値: テキスト (セミコロン区切りのドメイン名のリスト)

接続時に 4D Server から送信される証明書について、信頼できるドメイン名のリストです。クライアントアプリケーションは、CertificateAuthoritiesCertificates で証明書の認証局を検証した後、このリストを使用して証明書のドメイン名をチェックします (事前に CA の検証をおこなわないと、ドメイン名はチェックできません)。

バージョン​

接続を許可するクライアントのバージョンは、以下のキーを使用してサーバーによってチェックされます。現在のバージョン を参照してください。

CurrentVers​

値: バージョン番号

ビルドされるアプリケーションの現在のバージョン番号です。RangeVersMin および RangeVersMax が使用されていない場合、この番号は情報としてのみ使用されます。使用されている場合、サーバーはこの番号を読み取り、クライアントが許可された範囲内にあるかどうかをチェックします。

RangeVersMin​

値: バージョン番号

クライアントの最小バージョンです (例: 2)。これより前のバージョンのクライアントには、更新が促されます。RangeVersMax および CurrentVers と組み合わせて使用します。

RangeVersMax​

値: バージョン番号

クライアントの最大バージョンです (例: 3)。これより後のバージョンのクライアントには、更新が促されます。RangeVersMin および CurrentVers と組み合わせて使用します。

サーバー​

LastDataPathLookup​

サーバーアプリケーションの データリンクモード を定義します:

値データファイルパスの検索データファイルパスの保存先
InDbStructストラクチャーファイルに保存されたパスストラクチャーファイル内 (以前の動作)
ByAppNameLastDataPath.xml 内の最新のエントリーユーザー環境設定
ByAppPathexecutablePath がアプリケーションのパスに合致するエントリーユーザー環境設定

シングルユーザーアプリケーションにも同じキーが存在します: RuntimeVL/LastDataPathLookup。

MacCompiledDatabaseToWin​

値: パス

macOS 上で Silicon および Intel 用にコンパイルされたストラクチャーを格納しているフォルダーのパスです。MacCompiledDatabaseToWinIncludeIt と組み合わせて使用し、Windows 上でビルドされたサーバーに Silicon Mac クライアントからの接続を許可 します。

MacCompiledDatabaseToWinIncludeIt​

値: True / False (デフォルト)

Windows 上でサーバーをビルドする際、True の場合、MacCompiledDatabaseToWin で指定された macOS 上でコンパイルされたストラクチャーがサーバーに含まれます。

ServerEmbedsProjectDirectoryFile​

値: True / False (デフォルト)

True の場合、プロジェクトのユーザー設定フォルダーにある directory.json ファイルが、ビルドされたサーバーのユーザー設定フォルダーにコピーされます。ビルドしたサーバーアプリケーションにプロジェクトのユーザーとグループを埋め込む を参照してください。

ServerDataCollection​

値: True (デフォルト) / False

False の場合、ビルドされたサーバーでは 自動データ収集 が無効になります。

ServerStructureFolderName​

値: フォルダー名

組み込みアプリケーションフォルダー内の Active 4D Folder に作成される、サーバーキャッシュフォルダーのカスタム名です。デフォルトでは、組み込みアプリケーションの名前が使用されます。名前は OS のフォルダー名の規則に従う必要があります。サーバーキャッシュフォルダー を参照してください。

<CS>
  <ServerStructureFolderName>MyCache_v1</ServerStructureFolderName>
</CS>

HideAdministrationMenuItem​

値: True / False (デフォルト)

True の場合、ビルドされたサーバーでは:

  • ウィンドウ メニューから 管理 項目が削除されます。
  • 起動時に管理ウィンドウが表示されません (OPEN ADMINISTRATION WINDOW を使用すれば表示できます)。

HideDataExplorerMenuItem​

値: True / False (デフォルト)

True の場合、ビルドされたサーバーから データエクスプローラー メニュー項目が削除されます。

HideRuntimeExplorerMenuItem​

値: True / False (デフォルト)

True の場合、ビルドされたサーバーから ランタイムエクスプローラー メニュー項目とそのショートカット (macOS では Cmd+Shift+F9、Windows では Ctrl+Shift+F9) が削除されます。

クライアント​

ClientServerSystemFolderName​

値: フォルダー名

組み込みクライアントのローカルキャッシュフォルダー (Get 4D folder(4D Client database folder) が返すフォルダー) のカスタム名です。デフォルトでは、名前はアプリケーションとサーバーの情報から作成されます。名前は OS のフォルダー名の規則に従う必要があります。クライアントキャッシュフォルダー を参照してください。

ClientUserPreferencesFolderByPath​

値: True / False (デフォルト)

同じマシン上にある同じ名前の複数の組み込みクライアントが、それぞれ異なるサーバーに接続する場合に便利です。True の場合、各クライアントのユーザー環境設定フォルダー名の末尾に、クライアントのフルパスから算出された 3桁のハッシュが付加されるため、各クライアントが専用のフォルダーを持つことになります:

  • macOS: /Users/{UserAccount}/Library/Application Support/{ApplicationName} Client_{hash}
  • Windows: \Users\{UserAccount}\AppData\Roaming\{ApplicationName}_{hash}

この場合、Folder(fk user preferences folder) および Get 4D folder(Active 4D Folder) は、ハッシュ付きのパスを返します。

注

バイナリーデータベースでは、このキーには アプリケーション展開に新しいアーキテクチャーを使用 互換性オプションが必要です。

ClientWinSingleInstance​

値: True (デフォルト) / False

Windows では、デフォルトで同じセッション内に開けるクライアントアプリケーションのインスタンスは 1つのみです。複数のインスタンスを許可するには、このキーを False に設定します:

<CS>
  <ClientWinSingleInstance>False</ClientWinSingleInstance>
</CS>

ShareLocalResourcesOnWindowsClient​

値: True / False (デフォルト)

Windows の組み込みクライアントが、サーバーからダウンロードした ローカルリソース (.4dz ファイル、Libraries フォルダー、Resources フォルダーなど) を保存する場所を定義します:

  • False: ユーザーフォルダー内 \Users\{UserAccount}\AppData\Local\{ApplicationName}\{ServerInformation}_ClientFolderSignature\
  • True: 共有フォルダー内 \ProgramData\{ApplicationName}\{ServerInformation}_ClientFolderSignature\

共有フォルダーを使用すると、リモートデスクトップサービスや Citrix 環境において、ダウンロード時間とディスク容量を節約できます。このキーは、プロジェクトにおいて、Windows 上の組み込みクライアントに対してのみ考慮されます。

このキーが True の場合、クライアントの更新には ProgramData フォルダーへの読み書きアクセス権が必要です。管理者は以下の手順をおこなう必要があります:

  1. すべてのユーザーを切断し、組み込みクライアントへのアクセスを禁止します。
  2. 組み込みサーバーを更新します。
  3. リモートデスクトップサーバーの管理者セッションで組み込みクライアントを起動し、(自動または手動で) 更新させて、ローカルリソースを共有フォルダーにダウンロードさせます。
  4. 組み込みクライアントへのユーザーアクセスを復元します。

これにより、共有ローカルリソースへの同時書き込みや、アクセス権のエラーを防ぐことができます。
